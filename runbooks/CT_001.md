# CT_001: No multi-region CloudTrail

**Severity:** HIGH · **CIS AWS Foundations Benchmark v1.5.0:** 3.1

## Why this matters

Without a multi-region trail, API activity in regions you never visit (where attackers like to work) is simply not recorded. Every detection in detections/splunk depends on this trail existing.

## Verify

```bash
aws cloudtrail describe-trails --query 'trailList[].{Name:Name,MultiRegion:IsMultiRegionTrail}'
```

## Remediate

1. CloudTrail console > Trails > Create trail.
2. Enable for all regions, log management events (read and write), deliver to a dedicated, private S3 bucket.
3. Turn on log file validation at creation time.

```bash
aws cloudtrail create-trail --name org-trail --s3-bucket-name LOGBUCKET --is-multi-region-trail --enable-log-file-validation && aws cloudtrail start-logging --name org-trail
```

## After fixing

Re-run `cloudaudit scan` and confirm CT_001 no longer appears in the report.
